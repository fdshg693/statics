# プログラマブルアクション: ログ記録方針とデータフロー仕様

このドキュメントでは、プログラマブルアクションにおけるログ収集のアーキテクチャ、プレイヤー向けデバッグログとシステム向け開発ログの分離設計、およびログのデータフローについて解説します。

---

## 1. ログの分離設計と役割

本システムでは、発生するログを「ユーザースクリプトログ」と「システムログ」の2つに厳密に分離しています。これにより、プレイヤーのデバッグ体験向上とシステム内部動作の追跡性を両立させています。

```
                       ┌─────────────────────────┐
                       │   スクリプト実行エンジン  │
                       └────────────┬────────────┘
                                    │
                  ┌─────────────────┴─────────────────┐
                  ▼                                   ▼
      【ユーザースクリプトログ】                     【システムログ】
  ・プレイヤーが意図的に記述                    ・システム内部の挙動トレース
  ・`log()`, `console.log()`                 ・実行時間、成否、エラー詳細
  ・UI上の専用パネルに表示                      ・開発者コンソールへ出力
```

---

## 2. ユーザースクリプトログ (User Script Logs)

プレイヤーが自身の記述した自動戦闘スクリプトの分岐動作や変数の状態をトレースするために使用するログです。

### ログの出力インタフェース
スクリプト内からは、以下の2種類の呼び出しが許可されています。
1. **`log(message: string)`**: 最も標準的なログ出力API。
2. **`console.log(message: any)`**: 標準的なJSの開発体験に合わせた別名定義。

### ログ収集のメカニズム
1. **コンテキスト内蓄積**:
   `BattleScriptExecutor.execute` が呼ばれると、各戦闘ターンごとに `BattleScriptContextImpl` が生成されます。
   スクリプト内で `log(msg)` が呼ばれると、コンテキスト内のプライベート配列 `_logs` に文字列化されたメッセージが順次追加されます。
2. **実行結果としての返却**:
   スクリプト実行完了時、コンテキストから `_logs` をコピーし、`ScriptExecutionResult` オブジェクトの `logs` プロパティとして返却します。
3. **Vue 状態へのバインド**:
   `useBattle.ts` で実行結果を受け取り、Vue のリアクティブステート `scriptLogs.value = result.scriptLogs` へ格納します。
4. **UIのレンダリング**:
   戦闘画面のスクリプト管理コンソール内のログ履歴パネルにリアルタイムで出力されます。
   プレイヤーは **「ログクリア」** ボタンで `clearScriptLogs()` メソッドを呼び出し、表示されているログを手動で一掃できます。

---

## 3. システムログ (System Logs)

開発者がスクリプト実行エンジンの統合状態や実行効率、およびエラー発生時のトラブルシューティングを行うために出力されるログです。

### ログモジュールの使用
`ts/utils/logger.ts` に実装されているカスタムロガー（`createLogger`）を使用します。

* **`BattleScriptExecutor` ロガー**:
  スクリプトの評価プロセスを追跡します。
  * `log.group(...)`: スクリプトの実行開始。コード文字数、実行制限値を明示。
  * `log.debug(...)`: 実行完了時。最終的に決定されたコマンド、収集されたユーザースクリプトログの数、ミリ秒単位の実行時間を記録。
  * `log.error(...)`: サンドボックス内での例外発生時。エラーメッセージとスタックトレースを出力。
* **`ActionDecisionService` ロガー**:
  行動決定プロセスを追跡します。
  * `log.info(...)`: スクリプトの新規登録、有効状態の変更。構文エラー検出時の警告。
  * `log.debug(...)`: スクリプト優先での行動決定プロセス、UIへのフォールバック発生のイベントをトレース。
* **`useBattle` ロガー**:
  UI状態同期およびコマンドディスパッチ（`executeCommand`）の成功・不適合を記録します。

---

## 4. ログのデータフロー

1回の戦闘ターンにおける、ログが生成されてから画面に描画されるまでのライフサイクルです。

```mermaid
graph TD
    A[戦闘ターン開始] --> B[BattleScriptExecutor.execute 呼び出し]
    B --> C[BattleScriptContextImpl インスタンス生成]
    C --> D[サンドボックス実行]
    D -->|スクリプト内で log('HP: ' + player.hp) を実行| E(Context 内の _logs 配列へ push)
    D -->|スクリプト内で console.log('Heal cast') を実行| E
    D --> F[実行完了]
    F --> G[ScriptExecutionResult.logs として配列を格納]
    G --> H[ActionDecisionService.decideAction から useBattle へ返却]
    H --> I[useBattle.ts 内で scriptLogs.value に代入]
    I --> J[Vue リアクティブシステムによる検知]
    J --> K[バトルView の .script-log-panel 内に描画]
```
