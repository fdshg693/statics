# プログラマブルアクション: セキュリティ制約とサンドボックス設計仕様

このドキュメントでは、ユーザー入力スクリプトをクライアント（ブラウザ）上で安全に動作させるためのセキュリティ脅威モデル、多層防御アーキテクチャ、およびリソース制限の設計仕様について詳細に解説します。

---

## 1. 脅威モデル（想定されるリスク）

ユーザーに任意のJavaScriptコードの記述・実行を許可する場合、以下の重大なセキュリティおよび整合性の脅威が存在します。

* **状態の直接書き換え（チート）**: スクリプトがプレイヤーオブジェクトのHPプロパティを直接書き換えたり、ゲームエンジン内部のミュータブルな状態を不正に操作してゲームバランスを崩壊させる。
* **DOMおよびブラウザ環境へのアクセス（XSS・情報漏洩）**: スクリプトからブラウザの `window` や `document` にアクセスし、悪意あるDOM操作を実行したり、`localStorage` から他のセーブデータを窃取・書き換える。
* **ネットワーク通信（データ送出・詐取）**: `fetch` や `XMLHttpRequest` を使用して、プレイヤーのブラウザ上の機密データを外部のサーバーへ送信する。
* **ホスト環境のフリーズ（無限ループ）**: 不適切なループ処理（`while(true)` 等）が実行されることで、ブラウザのスレッドが占有され、ゲーム画面全体が応答なし（フリーズ）になる。
* **プロトタイプ汚染**: `Object.prototype` や組み込みオブジェクトのプロトタイプを汚染し、ゲームアプリケーション全体、あるいは他のモジュールの予期せぬ動作不良やセキュリティ脆弱性を引き起こす。

---

## 2. 多層防御アーキテクチャ

これらの脅威に対抗するため、本システムでは複数のセキュリティ防御層を重ねる「多層防御」を採用しています。

```
[ ユーザー記述スクリプト ]
           │
           ▼
┌──────────────────────────────────────────────┐
│ 1. キーワードスキャン (簡易静的解析)         │ ➡ 違反時は即時エラー
└──────────────────────────────────────────────┘
           │
           ▼
┌──────────────────────────────────────────────┐
│ 2. 厳格モード適用 ("use strict"; 強制)        │ ➡ グローバル 'this' へのアクセスを遮断
└──────────────────────────────────────────────┘
           │
           ▼
┌──────────────────────────────────────────────┐
│ 3. スコープマスキング (ホワイトリスト方式)   │ ➡ window, document, fetch 等を undefined 化
└──────────────────────────────────────────────┘
           │
           ▼
┌──────────────────────────────────────────────┐
│ 4. イミュータブル・スナップショット          │ ➡ player, enemy は Object.freeze 済み
└──────────────────────────────────────────────┘
```

### 第1層: キーワードスキャン（簡易静的解析）
スクリプトコードをパース・実行する前に、危険な動的コード実行手法を検出するスキャンを実施します。
* 正規表現 `/\beval\b|\bFunction\b/` を用いて、`eval` および `Function` コンストラクタの利用を検出します。
* 検出された場合、スクリプトはコンパイル・実行されず、即座に例外エラー（`Forbidden keyword detected in script`）がスローされます。

### 第2層: 厳格モードの強制 (`"use strict";`)
スクリプトは、内部的に以下のラッパーコードを結合した上で実行されます。
```javascript
"use strict";
// ユーザーのスクリプトコード
```
これにより、JavaScript の厳格モード（Strict Mode）が強制されます。
* グローバルオブジェクトの暗黙の参照である `this` が `undefined` になり、`this` を通じたグローバルオブジェクト（`window`）への不正アクセスを完全に遮断します。
* 読み取り専用プロパティ（フリーズされたプロパティ）への書き込み行為が発生した際、サイレントに無視されるのではなく、確実にランタイム例外をスローして実行を停止させます。

### 第3層: スコープマスキング（ホワイトリスト方式）
JavaScript の `Function` コンストラクタの特性を利用し、安全なオブジェクトのみがバインドされた隔離スコープ（サンドボックス）を構築します。

#### マスキングの仕組み
`Function` コンストラクタ引数で定義された仮引数名は、スクリプト実行時におけるスコープチェイン上で、グローバルオブジェクトよりも手前で解決されます。
これを利用し、危険なブラウザグローバル変数と同名の仮引数を用意してすべて `undefined` を渡すことで、グローバルアクセスを実質的に無効化（隠蔽）します。

```typescript
// 安全なグローバルオブジェクトとAPIのみをホワイトリスト登録
const sandboxGlobals = {
    // 公開データ・関数
    player: context.player,
    enemy: context.enemy,
    battleState: context.battleState,
    attack: () => context.attack(),
    heal: () => context.heal(),
    defend: () => context.defend(),
    flee: () => context.flee(),
    useItem: (itemId: string) => context.useItem(itemId),
    log: (msg: string) => context.log(msg),

    // 安全な組み込みユーティリティ
    Math: Math,
    console: {
        log: (msg: any) => context.log(String(msg))
    },

    // 危険なグローバルオブジェクトの完全な隠蔽（マスキング）
    window: undefined,
    document: undefined,
    fetch: undefined,
    XMLHttpRequest: undefined,
    localStorage: undefined,
    sessionStorage: undefined,
    setTimeout: undefined,
    setInterval: undefined,
    importScripts: undefined
};

// 実行フェーズ
const argNames = Object.keys(sandboxGlobals);
const argValues = Object.values(sandboxGlobals);

// サンドボックス関数を生成して評価
const scriptFunction = new Function(...argNames, wrappedCode);
scriptFunction(...argValues);
```

### 第4層: イミュータブル・スナップショット
スクリプトが参照する `player` や `enemy` などの状態データは、`ReadonlyStateWrapper.ts` にて `Object.freeze` が施されています。
* ネストされたオブジェクト（インベントリ内のアイテム配列など）も再帰的にフリーズ処理されており、スクリプト内で `player.hp = 999;` や `player.inventory.gold += 1000;` などの操作を行っても、Strict Mode の例外が発生し、ゲーム側のデータは一切変更されません。

## 3. 実行リソース制限 (Execution Limits)

悪意ある、あるいはバグを含んだスクリプトが、ブラウザ全体のメインスレッドを占有（ハングアップ）するのを防ぐため、以下の制約を設けています。

| 制限項目 | デフォルト値 | 説明 |
| :--- | :--- | :--- |
| **最大実行時間** (`maxExecutionTimeMs`) | `100ms` | スクリプトの開始から終了までの経過時間を `performance.now()` で計測。これを超過した場合は安全のためエラーとして処理されます。 |
| **最大命令数** (`maxInstructions`) | `1000` | スクリプト内で評価可能な処理単位の想定上限です（将来的なインタープリタ型サンドボックス導入に備えた予約定義）。 |

> [!WARNING]
> 現行の JS `new Function` によるネイティブ評価は、JSスレッド上で同期的に実行されます。
> 非常に複雑な無限ループ（例: `while(true) {}`）が記述された場合、一時的にスレッドがロックされる性質があります。
> 将来的なセキュリティアップデートでは、Web Worker 上での並行実行、または AST（抽象構文木）をベースとした段階的インタープリタ実行の導入により、この無限ループによる同期的ブロッキングを完全排除する計画が予定されています。
