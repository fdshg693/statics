# プログラマブルアクション: 影響範囲と後方互換性仕様

このドキュメントでは、プログラマブルアクション機能の導入が既存のゲームエンジン（`Game` クラス）、Vue 状態管理（`useBattle`）、UI 画面、および保存データ管理（`useSaveGame`）に与える影響範囲、および後方互換性の保証について解説します。

---

## 1. 影響範囲の要約

プログラマブルアクションは、既存の密結合されたターン制バトルフローに対して、**「非破壊的なデコレータ / ミドルウェア」**の形態で挿入されています。そのため、コアエンジン側の破壊的なインターフェース変更はありません。

```
【従来のゲームフロー】
[戦闘ターン開始] ──> [UIのボタン活性化] ──> [プレイヤー手動入力] ──> [ターン処理]

【新機能導入後のゲームフロー】
[戦闘ターン開始]
       │
       ▼
 ┌──────────────┐
 │スクリプト有効?│ ──(No)──> [UIのボタン活性化] ──> [プレイヤー手動入力] ──> [ターン処理]
 └──────┬───────┘
        │(Yes)
        ▼
 ┌──────────────┐
 │スクリプト評価│ ──(エラー / コマンド未決定)──> [UIのボタン活性化] ──> [プレイヤー手動入力]
 └──────┬───────┘
        │(コマンド決定)
        ▼
 [自動ターン処理実行]
```

---

## 2. 後方互換性の保証 (Backward Compatibility)

新機能導入にあたり、既存機能との後方互換性を保証するため、以下の設計配慮が行われています。

### 2.1 UI / View 層への互換性
* **UIトリガーの維持**:
  手動で戦闘を進めるための既存ボタン（「攻撃」「回復」「防御」「逃げる」およびアイテムスロット）はマークアップ構成も含めて100%維持されています。スクリプトが無効、あるいは未設定の標準状態では、ゲーム体験は完全に従来通りです。
* **useBattle 戻り値の後方互換性**:
  `useBattle.ts` が返すオブジェクトには、新しくスクリプト用の Ref やメソッド（`scriptEnabled`, `setScript` 等）が追加されましたが、既存のリアクティブ状態（`player`, `enemy`, `messages`, `battleState`）およびメソッド（`attackEnemy`, `playerHeal` 等）のシグネチャ（引数と戻り値）は完全に維持されています。

### 2.2 ゲームエンジンコア (`Game.ts`) への互換性
* **ゲームステート構造の非破壊**:
  `Game` クラスが持つ内部ステート構造、および `game.getState()` が返却するステートプロパティに対する破壊的変更はありません。
* **アクションメソッドの非破壊**:
  `game.attackEnemy()`, `game.playerHeal()` などのゲーム進行メソッドは、スクリプト実行エンジンからも `useBattle.ts` を仲介して通常通り呼び出されるため、アクション解決のロジックに変更は生じていません。

---

## 3. 具体的な変更点（行動決定の優先度シフト）

唯一の設計上の挙動変化は、戦闘における**「手動入力待ちから自動実行へのシフト」**です。

### 3.1 優先順位の定義
スクリプトが有効化されている場合、意思決定プロセスは常に**「スクリプトがUIに優先」**します。
* プレイヤーが「新しい戦闘」ボタンを押す、またはターン移行アニメーションが終了して次のターンが開始された段階で、`useBattle.ts` 内の `tryExecuteScript()` が自動で呼び出されます。
* スクリプトにより有効なコマンド（例: `AttackCommand`）が決定された場合、UI上の入力ボタンの活性化を挟むことなく、自動的にコマンド実行ロジックが走り、ターンが前進します。

### 3.2 統合・調整時の留意点
* **アニメーションと描画の競合**:
  自動行動により連続してターンが進行するため、戦闘ログ（`messages`）の追加が非常に高速に行われます。UIのログリスト自動スクロール処理（`scrollToLatestMessage`）には、描画の遅延を吸収するために `setTimeout(..., 50)` の非同期ラグが挿入されています。
* **セーブデータとの関係**:
  スクリプトコード自体は現在 `localStorage` に保存される設定（セーブスナップショット）とは独立しています。セーブデータをロードして再開した場合、スクリプトが有効であれば、その時点でのロード直後の戦闘ターンから即座にスクリプト判定が適用されます。
