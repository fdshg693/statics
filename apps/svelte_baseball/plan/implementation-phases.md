# Implementation Phases

## 方針

このファイルでは、実装時に進めやすい粒度でフェーズを分けます。
各フェーズは、前のフェーズの成果を土台にして段階的に積み上げる想定です。

## フェーズ 1: プロジェクト土台の作成

目的:

- `Vite + Svelte + TypeScript` の基本構成を用意する
- 静的配信を見据えた最小構成を整える

作業項目:

- Svelte アプリの初期構成を作成する
- `src/` のエントリポイントを用意する
- ビルド成果物が `dist/` に出ることを確認する
- 必要に応じて静的配信向けの設定ファイルを追加する

## フェーズ 2: ドメインモデルの定義

目的:

- 野球ゲームの状態と結果カテゴリを型で定義する

作業項目:

- カウント、アウト、得点、塁状況を表す型を決める
- 投球コースを表す型を決める
- 1 球ごとの結果カテゴリを列挙する
- ゲーム全体の状態オブジェクトを決める

## フェーズ 3: 結果判定ロジックの実装

目的:

- 投球コースから結果カテゴリを返す仕組みを作る

作業項目:

- コースごとの確率テーブルを定義する
- 乱数に基づいて結果カテゴリを選ぶ処理を作る
- 真ん中ほど打者有利、際どいコースほど投手有利の初期バランスを作る
- 将来の補正を加えやすい関数境界にする

## フェーズ 4: カウントと進塁処理の実装

目的:

- 1 打席と 1 イニングを成立させる

作業項目:

- ボール / ストライク / ファウルの更新処理を作る
- 四球と三振の判定を実装する
- インプレー時のアウト追加と進塁処理を実装する
- 3 アウトで終了する判定を実装する
- 打席終了時のカウントリセットを実装する

## フェーズ 5: UI の実装

目的:

- プレイヤーが遊べる画面を 1 画面で構成する

作業項目:

- 投球コースを選ぶ UI を作る
- カウント、塁状況、得点を表示する
- 直前結果を表示する
- ゲーム終了時の結果表示と再プレイ導線を作る

## フェーズ 6: 仕上げ

目的:

- MVP として一通り遊べる状態にする

作業項目:

- 確率バランスを最低限調整する
- 文言や表示崩れを調整する
- ビルドが通ることを確認する
- 静的ファイルとして配信できることを確認する

## フェーズ 7: 将来拡張の候補

MVP 完了後の候補:

- 球種追加
- カウント補正の強化
- 打者タイプ追加
- 難易度設定
- 成績保存
- 演出追加
